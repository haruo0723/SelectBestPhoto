## タスク概要

ペアメンバーだけが部門・候補へアクセスでき、自分の入力だけ編集でき、両者完了前は相手入力と結果を読めない Firestore Security Rules とRulesテストを実装する。Storage RulesはMVPでは全拒否を維持する。

- **後続タスク**: [TASK-0013](TASK-0013.md)

## 完了条件

- [ ] ペア外ユーザーの読み書きが拒否される。
- [ ] 本人だけが `inputs/{userId}` を作成・更新できる。
- [ ] 両者完了前の相手入力と結果読み取りが拒否される。
- [ ] 両者完了後の結果読み取りが許可される。
- [ ] Storage Rulesは全拒否のまま維持される。

## 実装詳細

### 1. Firestore Rulesを更新する 🔵

**信頼性**: 🔵 *security-rules.md の方針より*

`pairs/{pairId}.memberIds` に基づくアクセス制御、本人入力制御、結果公開条件を実装する。

**実装ファイル**: `firestore.rules`

### 2. Rulesテストを追加する 🔵

**信頼性**: 🔵 *security-rules.md Rulesテスト方針より*

Firebase Emulator Suite のテストに、ペア所属、本人入力、公開条件、Storage拒否のケースを追加する。

**実装ファイル**: `tests/firebase/rules.test.mjs`

### 3. 複雑な配列検証の責務を明確化する 🟡

**信頼性**: 🟡 *security-rules.md データ検証の注意より*

Rulesで表現しづらい重複検証やポイント配列検証はRepository/単体テストで補完し、Rulesでは型・上限・本人性・公開条件を優先する。
