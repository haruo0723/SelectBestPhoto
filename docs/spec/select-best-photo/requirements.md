## 2. プロダクト目的

SelectBestPhotoは、カップル2人が月ごとのベスト写真・動画を順位付きで登録し、両者の入力完了後に結果発表を楽しめるiPhoneアプリである。月間ベストを起点に年間ベスト候補、年間TOP5、敗者復活枠、年ごとのカスタム部門を扱い、2024年以降の思い出を後から見返せるようにする。🔵

## 3. スコープ

### 3.1 対象範囲

- iPhone写真ライブラリから写真、動画、Live Photosを選択して登録できる。🔵
- Firebase Anonymous Authenticationとペアコードで、2人のユーザーを同じカップルデータへ参加させる。🔵
- Cloud Firestoreで入力状態、順位、設定、公開状態、Storage参照を同期する。🔵
- Firebase Cloud Storageで軽量化済みの写真、動画、Live Photos関連データ、関連画像を保存する。🔵
- 月間ベスト、年間ベスト候補、年間TOP5、カスタム部門、テキスト候補型カスタム部門、敗者復活枠を登録、編集、リセット、結果発表できる。🔵
- 2024年以降の月間・年間結果を閲覧し、リセットなしで結果発表演出を再視聴できる。🔵
- iOS 18以降のiPhone専用SwiftUIアプリとして実装する。🔵

### 3.2 対象外

- アルバム単位での一括読み込み。🔵
- 通知機能。🔵
- App Store公開。🔵
- 書き出し機能。🔵
- iPad専用レイアウトまたはiPad最適化。🔵

## 4. 機能要件

### 4.1 初期利用、認証、ペア参加

- When ユーザーが初めてアプリを利用する場合、システムはFirebase Anonymous Authenticationでユーザーを内部識別する。🔵
- When 片方のユーザーがペアを作成する場合、システムは相手が入力できるペアコードを発行する。🔵
- When もう一方のユーザーがペアコードを入力する場合、システムは同じカップルデータに参加させる。🔵
- While ペアに参加している場合、システムはCloud Firestoreを通じて2人の入力状態と結果を同期する。🔵
- システムは明示的なログイン画面を設けない。🔵

### 4.2 プロフィールと設定

- ユーザーは自分の表示名とアイコンを設定、変更できる。🔵
- ユーザーは年月ごとの月間ベスト件数を設定でき、初期値は3件とする。🔵
- ユーザーは年ごと、月ごとの年間ベスト候補件数を設定でき、初期値は3件とする。🔵
- ユーザーは年ごとの敗者復活枠件数を1-2件の範囲で設定できる。🔵
- ユーザーは年ごとのカスタム部門を複数作成、管理できる。🔵
- ユーザーはテキスト候補型カスタム部門の順位別ポイント、入力対象順位、発表対象順位を部門ごとに管理できる。🔵

### 4.3 メディア選択、保存、再生

- ユーザーはiPhone写真ライブラリから写真、動画、Live Photosを選択できる。🔵
- システムはFirebase Cloud Storageへ保存する前に、アプリ表示・再生用にメディアを軽量化する。🔵
- システムは写真を表示用に圧縮した画像として保存する。🔵
- システムは動画をアプリ上で再生可能な圧縮版動画として保存する。🔵
- システムはLive Photosをアプリ上で再生可能な形式で、静止画部分とモーション部分に分けて保存する。🔵
- システムはユーザーのiPhone写真ライブラリ上の元データを変更または削除しない。🔵
- 読み込めないファイルの扱い、圧縮基準、メタデータ保持方針は技術検証で決定する。🔵

### 4.4 月間ベスト

- ユーザーは今月を含む過去の月に対して、月間ベストを登録できる。🔵
- ユーザーは設定件数まで、写真または動画を順位付きで登録できる。🔵
- ユーザーは月間ベストを下位から順番に入力する。🔵
- ユーザーは入力中に、ここまで選んだ写真・動画と順位を見返せる。🔵
- ユーザーは入力中または入力完了後に、自分の選択内容や順位を修正できる。🔵
- ユーザーは相手の月間ベスト入力を編集できない。🔵
- When 月間データをリセットする場合、システムは対象月の全体リセットであることを確認ダイアログで示す。🔵
- If 月間データがリセットされた場合、両方のユーザーが再入力を完了すると結果発表を再度見られる。🔵

### 4.5 入力状態と公開条件

- システムは入力状態を未入力、入力中、入力完了として管理する。🔵
- システムは月間ベスト、年間ベスト、カスタム部門、テキスト候補型カスタム部門の入力状態を表示できる。🔵
- While 片方だけが入力完了している場合、システムは相手の入力内容を表示しない。🔵
- When 両方のユーザーが入力完了した場合、システムは結果発表画面で互いの結果を表示できる。🔵
- 結果発表の公開条件は、クライアント表示制御だけでなくFirestore Security Rulesでも保護する。🔵

### 4.6 結果発表

- 結果発表画面は下位から上位へ順番に結果を表示する。🔵
- 結果発表画面は順位が映える視覚表現を使い、1位、2位、3位の差が自然に伝わるUIにする。🔵
- 結果発表画面は月間ベスト、年間ベスト、カスタム部門で同様の体験を提供する。🔵
- ユーザーは過去結果の結果発表演出を、リセットなしで再視聴できる。🔵
- 具体的なアニメーション、質感、見せ方はデザイン検討で決定する。🔵

### 4.7 年間ベスト候補

- ユーザーは月間ベストから年間ベスト候補へ進める写真・動画を選べる。🔵
- 年間ベスト候補へ進める件数は、年ごと、月ごとに保持する。🔵
- 月間ベスト件数と年間ベスト候補件数は別々に設定できる。🔵

### 4.8 年間ベスト

- ユーザーは年間ベストとしてTOP5を順位付きで選べる。🔵
- 年間ベストTOP5は自分と相手がそれぞれ入力する。🔵
- ユーザーは年間ベストTOP5を下位から順番に入力する。🔵
- ユーザーは自分の年間ベスト入力を編集でき、相手の入力は編集できない。🔵
- When 年間ベストをリセットする場合、システムは対象年の年間ベスト全体リセットであることを確認ダイアログで示す。🔵
- If 年間ベストがリセットされた場合、両方のユーザーが再入力を完了すると結果発表を再度見られる。🔵

### 4.9 メディア型カスタム部門

- ユーザーは年ごとに複数のカスタム部門を作成できる。🔵
- ユーザーは各カスタム部門で、年間ベスト候補に入った写真・動画からTOP3を選べる。🔵
- ユーザーはカスタム部門TOP3を下位から順番に入力する。🔵
- ユーザーは自分のカスタム部門入力を編集でき、相手の入力は編集できない。🔵
- When カスタム部門TOP3をリセットする場合、システムは対象部門の全体リセットであることを確認ダイアログで示す。🔵

### 4.10 テキスト候補型カスタム部門

- ユーザーは写真・動画以外の候補項目から選ぶ年間カスタム部門を作成できる。🔵
- ユーザーは候補項目を`.xlsx`、`.csv`、手入力で追加できる。🔵
- ExcelまたはCSVから読み込む候補項目は候補名のみとする。🔵
- ユーザーはアプリ上で候補項目を編集できる。🔵
- ユーザーは候補項目ごとに任意で関連画像を1枚添付できる。🔵
- ユーザーはテキスト候補型カスタム部門で順位付きのベストを選べる。🔵
- システムは部門ごとの順位別ポイント設定に従って結果を集計する。🔵
- ユーザーは自分の入力を編集でき、相手の入力は編集できない。🔵
- When テキスト候補型カスタム部門をリセットする場合、システムは対象部門の全体リセットであることを確認ダイアログで示す。🔵

### 4.11 敗者復活枠

- ユーザーは年間候補に漏れたものも含め、全ての写真・動画から敗者復活枠を選べる。🔵
- 敗者復活枠は年ごとに1-2件の範囲で設定できる。🔵
- 敗者復活枠で選んだ写真・動画は、年間ベストTOP5やメディア部門の候補に含める。🔵
- ユーザーは敗者復活枠を編集、リセットできる。🔵
- When 敗者復活枠をリセットする場合、システムは対象年の敗者復活枠全体リセットであることを確認ダイアログで示す。🔵
- リセットにより不要になったFirebase Cloud Storage上のメディアは削除する。🔵

### 4.12 過去結果閲覧

- システムは2024年以降の月間・年間結果を保持できる。🔵
- ユーザーは過去の月間結果と年間結果を見返せる。🔵
- ユーザーは過去の結果発表演出を再視聴できる。🔵

## 5. 非機能要件

### 5.1 プラットフォーム

- アプリはiOS 18以降のiPhoneのみを対象とする。🔵
- UIはSwiftUI、画面遷移はNavigationStackを基本とする。🔵
- 状態管理はSwiftUI標準の状態管理とObservationを基本とする。🔵
- 非同期処理はSwift Concurrencyを利用する。🔵

### 5.2 パフォーマンス

- システムは写真・動画のアップロード、表示、再生で保存容量と転送量が過度に増えないよう軽量化する。🔵
- 想定メディア件数、サムネイル生成時間、表示待ち時間、圧縮方式、画質、サイズ基準は技術検証で決定する。🔵
- ローカルキャッシュは実装段階でファイルキャッシュまたはSwiftDataを検討する。🔵

### 5.3 信頼性

- アプリ再起動後も、保存済みの月間ベスト、年間ベスト候補、敗者復活枠、結果を維持する。🔵
- エラー発生時は作業状態が可能な限り失われないようにする。🔵
- Storageメディア削除では、必要なメディアを巻き込まないよう参照元、所有スコープ、削除対象を設計時に明確化する。🔵

### 5.4 セキュリティ・プライバシー

- Firestore RulesとStorage Rulesで、ペアに属するユーザーだけが対象データへアクセスできるようにする。🔵
- 結果発表の公開条件はFirestore Rulesでも保護する。🔵
- ペアコード、ユーザーID、写真パス、個人情報をログに出さない。🔵
- 写真・動画をFirebaseへアップロードする前に、ユーザーが対象を認識できるUIにする。🔵
- App Checkは本番に近い運用へ進む前に導入を検討する。🔵
- `GoogleService-Info.plist` の管理方針はFirebaseプロジェクト作成時に決める。🔵

### 5.5 ユーザビリティとアクセシビリティ

- Apple標準のナビゲーション、入力、共有、アクセシビリティの作法を優先する。🔵
- 写真・動画・ランキングを主役にし、説明文は必要最小限にする。🔵
- Dynamic Type、VoiceOver、十分なコントラスト、44pt以上のタップ領域を意識する。🔵
- 誤操作しやすいリセット操作には確認手段を用意する。🔵
- 月間ベスト、年間ベスト候補、敗者復活枠、結果は視覚的に区別しやすい表示にする。🔵
