## 確認事項（判断が必要）

- [x] **MVPの候補数・入力順位数の上限** 🔵 *ユーザヒアリング2026-06-24*
  - 確定したこと: 1部門あたりの候補数上限は100件。
  - 確定したこと: 入力対象順位の上限、発表対象順位の上限、ポイント設定行数の上限は50件。
  - 現時点で確定済み: 部門数は1年あたり最大30部門程度。
  - 設計で具体化すること: 100件の候補を扱う候補一覧UI、50位までの順位入力UI、50行のポイント設定UIをiPhone画面で破綻させない表示方式。
  - 影響範囲: Firestoreドキュメント分割、インデックス要否、順位入力UIの操作性、Dynamic Type時の表示、Rulesテスト・ユニットテストのデータ量。
  - 判断タイミング: 上限値は確定済み。`kairo-design` では保存形式と画面表現を決める。
  - 関連要件: REQ-006, REQ-007, NFR-001

- [x] **候補・設定確定前後の編集ルール** 🔵 *ユーザヒアリング2026-06-24*
  - 確定したこと: 候補項目、入力対象順位、発表対象順位、順位別ポイントが確定されるまで、どちらのユーザーも順位入力できない。
  - 確定したこと: 候補・設定の確定後は、候補追加、候補編集、候補削除、入力対象順位、発表対象順位、ポイント設定の変更を制限する。
  - 確定したこと: 確定前に2人が同時に候補を追加した場合、同名候補も含めて追加を失わずに保存する。
  - 設計で具体化すること: 候補を個別ドキュメント化するか、確定操作時にトランザクションで整合性を検証するか、候補表示順を `createdAt` / 明示的な並び順のどちらで扱うか。
  - 影響範囲: Firestoreスキーマ、Repositoryの更新API、候補管理UIの確定表示、Firestore Rules、同時編集テスト。
  - 関連要件: REQ-019, REQ-107, REQ-108, REQ-109, REQ-110, EDGE-003

- [ ] **CSV / XLSX読み込みと関連画像添付の復帰フェーズ** 🟡 *MVPスコープ調整*
  - 決めること: CSV読み込み、XLSX読み込み、関連画像添付、Cloud Storage保存をどの順番で後続実装へ戻すか。
  - 現時点で確定済み: 今回のMVPではCSV / XLSX読み込み、関連画像の選択・保存・アップロード、Cloud Storage連携は実装しない。
  - 現時点で確定済み: 候補一覧、候補編集、結果画面には関連画像枠またはプレースホルダーを表示できるようにする。
  - 判断候補: CSVだけを先に戻す / CSVとXLSXを同時に戻す / 関連画像添付を先に戻す / ファイル読み込みと画像添付をまとめて戻す。
  - 影響範囲: DocumentPicker相当の導入タイミング、ファイル形式バリデーション、画像メタデータ方針、Storage Rules、既存候補データとの互換性。
  - 判断タイミング: MVP実装完了後、次の仕様作成時。
  - 関連要件: REQ-301, REQ-302
