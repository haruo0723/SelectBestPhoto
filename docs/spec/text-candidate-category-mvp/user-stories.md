## エピック1: 部門と候補の準備

### ストーリー 1.1: 年ごとのテキスト候補部門を作成して設定する 🔵

**信頼性**: 🔵 *docs/requirements.md 6.6, 6.11 / ユーザヒアリング2026-06-24*

**私は** カップルのユーザー **として**
**年ごとにエピソード部門や笑った部門のようなテキスト候補部門を複数作成し、入力前に設定を整えたい**
**そうすることで** 写真や動画ではない思い出も年間ランキングとして選べる。

**関連要件**: REQ-001, REQ-002, REQ-006, REQ-007, REQ-008, REQ-016

**詳細シナリオ**:
1. 年を選択する。
2. 部門名を入力する。
3. 入力対象順位、発表対象順位、順位別ポイントを設定する。
4. 部門を保存する。

**前提条件**:
- ユーザーはFirebase Anonymous Authenticationで識別されている。
- ユーザーはペアに参加済みである。

**優先度**: Must Have

### ストーリー 1.2: 候補を手入力で管理する 🔵

**信頼性**: 🔵 *docs/requirements.md 6.6 / MVPスコープ*

**私は** カップルのユーザー **として**
**候補項目を手入力で追加・編集したい**
**そうすることで** その年のエピソードや出来事をランキング候補として整理できる。

**関連要件**: REQ-003, REQ-004, REQ-005, REQ-017, REQ-202, REQ-408

**詳細シナリオ**:
1. 部門の候補管理画面を開く。
2. 候補名を入力して追加する。
3. 必要に応じて候補名を編集する。
4. 不要な候補を削除する。

**制約事項**:
- MVPではCSV / XLSX読み込みは行わない。
- MVPでは関連画像の選択・保存・アップロードは行わない。
- 候補一覧、候補編集、結果表示には関連画像枠を用意する。

**優先度**: Must Have

---

### ストーリー 1.3: 候補と設定を確定してから入力を始める 🔵

**信頼性**: 🔵 *ユーザヒアリング2026-06-24*

**私は** カップルのユーザー **として**
**相手と候補やポイント設定を確定してから順位入力を始めたい**
**そうすることで** 入力中に候補やポイントが変わらず、2人の順位入力と集計結果の整合性を保てる。

**関連要件**: REQ-019, REQ-107, REQ-108, REQ-109, REQ-110, EDGE-003

**詳細シナリオ**:
1. 候補・設定が未確定の部門を開く。
2. 2人がそれぞれ候補を追加する。
3. 別名候補は両方保存される。
4. 同名候補も別候補として両方保存される。
5. 候補、入力対象順位、発表対象順位、順位別ポイントを確認する。
6. 候補・設定を確定する。
7. 確定後は順位入力へ進める。
8. 確定後は候補と部門設定の変更が制限される。

**優先度**: Must Have

## エピック2: 自分の順位入力

### ストーリー 2.1: 候補から順位付きで選ぶ 🔵

**信頼性**: 🔵 *docs/requirements.md 6.6*

**私は** カップルのユーザー **として**
**候補から順位付きでベストを選びたい**
**そうすることで** 自分が印象に残った出来事を相手と比べて楽しめる。

**関連要件**: REQ-009, REQ-010, REQ-102, REQ-203

**詳細シナリオ**:
1. 候補・設定が確定済みの対象部門を開く。
2. 対象部門の入力画面を開く。
3. 設定された入力対象順位分の候補を選ぶ。
4. 同じ候補を重複選択せずに順位を確定する。
5. 入力完了にする。

**前提条件**:
- 候補項目、入力対象順位、発表対象順位、順位別ポイントが確定済みである。
- 入力対象順位以上の候補が存在する。

**優先度**: Must Have

---

### ストーリー 2.2: 入力状況だけを相手に伝える 🔵

**信頼性**: 🔵 *docs/requirements.md 6.3, 6.6*

**私は** カップルのユーザー **として**
**相手が完了するまでは自分の選択内容を見られないようにしたい**
**そうすることで** 結果発表の楽しみを保てる。

**関連要件**: REQ-103, REQ-204, REQ-402, REQ-403, REQ-405

**詳細シナリオ**:
1. 自分の入力を完了する。
2. 相手が未完了の場合、相手には自分の入力内容が表示されない。
3. 相手には入力状況だけが表示される。

**優先度**: Must Have

## エピック3: 結果発表と再入力

### ストーリー 3.1: 両方完了後に集計結果を見る 🔵

**信頼性**: 🔵 *docs/requirements.md 6.3, 6.6, 8*

**私は** カップルのユーザー **として**
**2人の入力が揃ったらポイント集計結果を見たい**
**そうすることで** 2人で選んだ年間の思い出を楽しく振り返れる。

**関連要件**: REQ-011, REQ-012, REQ-104, REQ-205

**詳細シナリオ**:
1. 自分と相手が入力完了する。
2. システムが順位別ポイントに従って候補ごとの合計点を計算する。
3. 発表対象順位までの集計結果を表示する。

**優先度**: Must Have

---

### ストーリー 3.2: 部門をリセットして再入力する 🔵

**信頼性**: 🔵 *docs/requirements.md 6.6 / 年間・カスタム部門リセット要件*

**私は** カップルのユーザー **として**
**対象部門を全体リセットして再入力したい**
**そうすることで** 誤った候補や順位で完了した場合もやり直せる。

**関連要件**: REQ-013, REQ-014, REQ-105, REQ-106

**詳細シナリオ**:
1. 部門のリセット操作を選ぶ。
2. 全体リセットであることを確認する。
3. リセット後、2人分の入力状態が未入力に戻る。
4. 候補と部門設定が確定前状態へ戻る。
5. 必要に応じて候補や設定を修正し、再度確定する。
6. 再入力後、もう一度結果を表示できる。

**優先度**: Must Have
