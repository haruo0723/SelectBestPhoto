# requirements.md

このファイルは、SelectBestPhoto の要件を整理するためのドキュメントです。
未確定の項目は「未定」または「技術検証で決定」として残し、壁打ちしながら段階的に具体化します。

## 1. 背景

カップルで、月ごとのベスト写真・動画を選び、結果を見返せるようにする。
お互いがベストだと思う写真・動画を登録し、両方の入力完了後に結果発表画面で相手の結果を確認できるようにする。
さらに、月ごとのベスト写真・動画から年間ベスト候補を作り、年ごとの思い出を振り返れるようにする。
年間ベストでは、それぞれのユーザーが年間TOP5を選べるようにする。
年間ベスト候補に入った写真・動画から、カスタム部門ごとのTOP3も選べるようにする。

- 月ごとの思い出を、写真・動画として整理して残したい。
- お互いが選んだベスト写真・動画を、結果発表の体験として楽しみたい。
- 月ごとの結果だけでなく、年間のベスト写真・動画も選べるようにしたい。
- 月間・年間の結果を、順位が映えるUIで楽しく見たい。
- アプリ全体を、シンプルで使いやすくしつつ、平坦になりすぎないおしゃれなデザインにしたい。
- 2024年以降の過去の結果も見返せるようにしたい。

## 2. 目的

カップルがそれぞれ月ごとのベスト写真・動画を登録し、結果発表画面でお互いの結果を確認できるようにする。
月間ベストから年間ベスト候補を作成し、2024年以降の月間・年間の結果を後から見返せるようにする。
年間ベストはそれぞれのユーザーがTOP5を選び、年間ベスト候補に入った写真・動画から部門別TOP3も選べるようにする。

## 3. 想定ユーザー

- 主ユーザー: カップル
- 利用形態: 2人のユーザーがお互いに写真・動画を登録し、相手の結果を確認する
- 利用頻度: 未定
- 利用環境: iPhone
- 写真枚数の想定: 技術検証で決定

## 6. 機能要件

### 6.1 写真の読み込み

- ユーザーは、iPhoneの写真ライブラリから登録対象の写真・動画を指定できる。
- ユーザーは、写真ライブラリから複数の写真・動画を選択して、月間ベストに登録できる。
- システムは、Live Photos、写真、動画を扱える。
- 読み込めないファイルがある場合のエラー表示・スキップ方針は技術検証で決定する。

### 6.2 月間ベスト登録

- ユーザーは、今の月を含めた過去の月に対して、いつでも月間ベストを登録できる。
- ユーザーは、月ごとに設定された件数まで月間ベストを登録できる。
- ユーザーは、月間ベストを順位付きで入力する。
- 月間ベストは、下位から順番に入力する。
- ユーザーは、入力中にここまで選んだ写真・動画を見返せる。
- ユーザーは、入力中または入力完了後に、選んだ写真・動画や順位を修正できる。
- ユーザーが編集できるのは、自分の月間ベスト入力のみとする。
- ユーザーは、相手の月間ベスト入力を編集できない。
- 月間ベストの件数は、年月ごとに設定できる。
- 月間ベストの初期件数は3件とする。
- 例: 2025年7月は3件、2025年8月は2件、2026年7月は4件にできる。
- 月間ベストの件数設定が5件の場合、自分は最大5件、相手も最大5件を登録できる。
- 月間ベストの件数は、年間ベスト候補へ進める件数とは別に設定できる。
- ユーザーは、各月の月間ベストを編集できる。
- ユーザーは、各月のデータをリセットできる。
- 月間データをリセットした場合、ユーザーは再入力できる。
- 月間データのリセット後、両方のユーザーが再度入力完了すると、結果発表をもう一度見られる。
- 月間データのリセットは、自分だけではなく対象月の全体リセットとして扱う。
- 月間データをリセットする前に、システムは確認ダイアログを表示する。

### 6.3 結果発表

- システムは、自分と相手の両方が入力完了するまで、結果発表画面で相手の結果を表示しない。
- システムは、相手の入力内容を表示せずに、入力状況だけを表示できる。
- 入力状況は、未入力、入力中、入力完了を区別できる。
- 入力状況表示は、月間ベスト、年間ベスト、カスタム部門に対応する。
- システムは、両方の入力完了後に結果発表画面を表示できる。
- 結果発表画面では、下位から順番にめくられていくように結果を表示する。
- 結果発表画面は、演出としてオシャレに感じられるデザインを目指す。
- 結果発表画面では、順位が見栄えするUIを用いる。
- 例: 1位は金メダル、2位は銀メダルなど、順位に応じた視覚表現を活用する。
- 結果発表画面は、下位から上位へ向かって期待感が高まる演出にする。
- 結果発表画面は、シンプルだが平坦になりすぎない、特別感のあるデザインにする。
- 月間ベスト、年間ベスト、カスタム部門の結果発表で同様の体験を提供する。

### 6.4 年間ベスト候補

- ユーザーは、月間ベストから年間ベスト候補へ進める写真・動画を選べる。
- 年間ベスト候補へ進める件数は、月ごとに設定できる。
- 年間ベスト候補へ進める件数は、年ごとに別の設定として保持する。
- 年間ベスト候補へ進める件数の初期値は3件とする。
- 例: 2025年7月は2件、2025年8月は1件を年間ベスト候補へ進める。
- 月間ベストの件数と、年間ベスト候補へ進める件数は別々に設定できる。
- 例: 月間ベストは10件、年間ベスト候補へ進める件数は2件にできる。

### 6.5 年間ベスト

- ユーザーは、年間ベストとしてTOP5を選べる。
- 年間ベストTOP5は、自分と相手がそれぞれ選べる。
- ユーザーは、年間ベストTOP5を順位付きで入力する。
- 年間ベストTOP5は、下位から順番に入力する。
- ユーザーは、年間ベスト入力中にここまで選んだ写真・動画を見返せる。
- ユーザーは、年間ベスト入力中または入力完了後に、選んだ写真・動画や順位を修正できる。
- ユーザーが編集できるのは、自分の年間ベスト入力のみとする。
- ユーザーは、相手の年間ベスト入力を編集できない。
- 年間ベストは、自分と相手がそれぞれ入力し、両方の入力完了後に結果発表できる。
- ユーザーは、年間ベストを編集できる。
- ユーザーは、年間ベストをリセットできる。
- 年間ベストをリセットした場合、ユーザーは再入力できる。
- 年間ベストのリセット後、両方のユーザーが再度入力完了すると、結果発表をもう一度見られる。
- 年間ベストのリセットは、自分だけではなく対象年の年間ベスト全体リセットとして扱う。
- 年間ベストをリセットする前に、システムは確認ダイアログを表示する。
- 年間ベストTOP5とは別枠で、ユーザーはカスタム部門を作成できる。
- カスタム部門は、年ごとに別のデータとして保持する。
- ユーザーは、1年に複数のカスタム部門を作成できる。
- カスタム部門の例として、ぬいぐるみ部門、食べ物部門、エピソード部門、笑った部門などを作成できる。
- ユーザーは、各カスタム部門ごとにTOP3を選べる。
- ユーザーは、カスタム部門TOP3を順位付きで入力する。
- カスタム部門TOP3は、下位から順番に入力する。
- ユーザーは、カスタム部門入力中にここまで選んだ写真・動画を見返せる。
- ユーザーは、カスタム部門入力中または入力完了後に、選んだ写真・動画や順位を修正できる。
- ユーザーが編集できるのは、自分のカスタム部門入力のみとする。
- ユーザーは、相手のカスタム部門入力を編集できない。
- カスタム部門TOP3は、年間ベスト候補に入った写真・動画から選べる。
- カスタム部門TOP3は、自分と相手がそれぞれ入力し、両方の入力完了後に結果発表できる。
- ユーザーは、カスタム部門TOP3を編集できる。
- ユーザーは、カスタム部門TOP3をリセットできる。
- カスタム部門TOP3をリセットした場合、ユーザーは再入力できる。
- カスタム部門TOP3のリセット後、両方のユーザーが再度入力完了すると、結果発表をもう一度見られる。
- カスタム部門TOP3のリセットは、自分だけではなく対象部門の全体リセットとして扱う。
- カスタム部門TOP3をリセットする前に、システムは確認ダイアログを表示する。

### 6.6 テキスト候補型カスタム部門

- ユーザーは、写真・動画以外の候補項目から選ぶカスタム部門を作成できる。
- テキスト候補型カスタム部門は、年間のみで利用する。
- テキスト候補型カスタム部門の例として、エピソード部門、笑った部門などを作成できる。
- ユーザーは、候補項目をExcelファイルから読み込める。
- Excelファイルから読み込む候補項目は、候補名のみとする。
- ユーザーは、候補項目を手入力で追加できる。
- ユーザーは、アプリ上で候補項目を編集できる。
- ユーザーは、アプリ上で候補項目を入力・編集する際に、任意で関連画像を添付できる。
- ユーザーは、Excelファイルから読み込んだ候補項目にも、後からアプリ上で関連画像を添付できる。
- ユーザーは、テキスト候補型カスタム部門で順位付きのベストを選べる。
- テキスト候補型カスタム部門は、ポイント制で集計する。
- ユーザーは、順位ごとのポイントを部門ごとに設定できる。
- 例: 1位は10pt、2位は5ptなどを部門ごとに設定できる。
- ユーザーは、何位まで入力するかを部門ごとに設定できる。
- ユーザーは、何位までを結果発表の対象に含めるかを部門ごとに設定できる。
- テキスト候補型カスタム部門も、自分と相手がそれぞれ入力し、両方の入力完了後に結果発表できる。
- ユーザーが編集できるのは、自分のテキスト候補型カスタム部門入力のみとする。
- ユーザーは、相手のテキスト候補型カスタム部門入力を編集できない。
- テキスト候補型カスタム部門のリセットは、自分だけではなく対象部門の全体リセットとして扱う。
- テキスト候補型カスタム部門をリセットする前に、システムは確認ダイアログを表示する。

### 6.7 敗者復活枠

- ユーザーは、年間候補に漏れたものも含め、全ての写真・動画から敗者復活枠を選べる。
- 敗者復活枠は、1-2件の範囲で選択できる。
- 敗者復活枠の件数は、年ごとに設定画面などで変更できる。
- 敗者復活枠で選んだ写真・動画は、年間ベストTOP5やメディア部門の候補に含める。
- ユーザーは、敗者復活枠を編集できる。
- ユーザーは、敗者復活枠をリセットできる。
- 敗者復活枠のリセットは、自分だけではなく対象年の敗者復活枠全体リセットとして扱う。
- 敗者復活枠をリセットする前に、システムは確認ダイアログを表示する。
- リセットにより不要になったFirebase Cloud Storage上のメディアは削除する。

### 6.8 過去結果の閲覧

- システムは、2024年から開始した月間・年間の結果を保持できる。
- ユーザーは、過去の月間結果を見返せる。
- ユーザーは、過去の年間結果を見返せる。
- ユーザーは、リセットしなくても過去の結果発表演出を再視聴できる。

### 6.9 メディア再生

- ユーザーは、アプリ上で写真を表示できる。
- ユーザーは、アプリ上で動画を再生できる。
- ユーザーは、アプリ上でLive Photosを再生できる。

### 6.10 バックエンド

- システムは、Firebaseをバックエンドとして利用する。
- ユーザー向けの明示的なログイン画面は設けない。
- システムは、Firebase Anonymous Authenticationでユーザーを内部的に識別する。
- 2人のユーザーは、ペアコードなどで同じカップルデータに参加する。
- 片方のユーザーは、ペアを作成してペアコードを発行できる。
- もう一方のユーザーは、共有されたペアコードを入力して同じペアに参加できる。
- システムは、Cloud Firestoreで月間ベスト、年間ベスト候補、年間ベスト、カスタム部門、テキスト候補型カスタム部門、敗者復活枠、入力状況、設定を管理する。
- システムは、Firebase Cloud Storageで写真・動画・Live Photos関連データ、テキスト候補型カスタム部門の関連画像を保存する。
- Firebase Cloud Storageには、元データではなくアプリ表示・再生用に軽量化したデータを保存する。
- 写真は、表示用に圧縮した画像を保存する。
- 動画は、アプリ上で再生可能な圧縮版動画を保存する。
- Live Photosは、アプリ上で再生可能な形式で静止画部分とモーション部分を保存する。
- 元データはユーザーのiPhone写真ライブラリに残す前提とし、アプリは元データを直接変更しない。
- システムは、2人のユーザー間で入力状況と結果を同期する。

### 6.11 設定

- ユーザーは、自分の表示名を設定できる。
- ユーザーは、自分のアイコンを設定できる。
- ユーザーは、設定画面で自分の表示名とアイコンを変更できる。
- ユーザーは、設定画面で年月ごとの月間ベスト件数を変更できる。
- ユーザーは、設定画面で年ごと・月ごとの年間ベスト候補件数を変更できる。
- ユーザーは、設定画面で年ごとの敗者復活枠件数を変更できる。
- ユーザーは、設定画面でカスタム部門を管理できる。
- ユーザーは、設定画面でテキスト候補型カスタム部門の順位別ポイントと発表対象順位を管理できる。
- ユーザーは、設定画面でテキスト候補型カスタム部門の入力対象順位を管理できる。

## 7. 非機能要件

### 7.1 パフォーマンス

- 想定枚数の写真・動画を扱った場合の操作性基準は技術検証で決定する。
- サムネイル生成やメディア表示の待ち時間基準は技術検証で決定する。
- 写真・動画のアップロード、表示、再生では、保存容量と転送量が過度に増えないようにする。
- Firebase Cloud Storageへ保存するメディアは、表示・再生に支障がない範囲で軽量化する。
- 写真・動画・Live Photosの圧縮方式、画質、サイズ基準は技術検証で決定する。

### 7.2 信頼性

- 元画像を意図せず変更・削除しない。
- iPhone写真ライブラリ上の元データは、アプリから直接変更・削除しない。
- 保存済みの月間ベスト、年間ベスト候補、敗者復活枠、結果が、アプリ再起動後も維持される。
- エラー発生時に、作業状態が可能な限り失われない。

### 7.3 セキュリティ・プライバシー

- 写真データを外部送信する場合は、明示的な許可を必要とする。
- Firebaseに写真・動画をアップロードする前に、ユーザーがアップロード対象を認識できるようにする。
- 個人情報を含む可能性があるメタデータの扱いを定義する。
- 通知機能は初期スコープに含めない。

### 7.4 ユーザビリティ

- 主要操作はキーボードでも実行できる。
- 月間ベスト、年間ベスト候補、敗者復活枠、結果は視覚的に区別しやすい表示にする。
- 誤操作しやすい操作には、取り消しまたは確認手段を用意する。
- アプリ全体のUIは、シンプルで操作しやすいことを優先する。
- デザインは平坦になりすぎないようにし、カード、余白、階層、質感、モーションなどで奥行きや特別感を出す。
- 写真・動画・ランキングが主役として映えるデザインにする。

## 8. 受け入れ基準

- Given 月間ベストの件数設定が5件の場合、When 自分が月間ベストを登録する場合、Then 自分は最大5件まで登録できる。
- Given 月間ベストの件数設定が5件の場合、When 相手が月間ベストを登録する場合、Then 相手も最大5件まで登録できる。
- Given 月間ベストを入力する場合、When 入力画面を開く場合、Then 下位の順位から順番に写真・動画を選択できる。
- Given 月間ベストを入力中の場合、When ここまで選んだ内容を確認する場合、Then 選択済みの写真・動画と順位を見返せる。
- Given 月間ベストを入力中または入力完了後の場合、When 修正する場合、Then 選んだ写真・動画や順位を変更できる。
