# SelectBestPhoto 受け入れ基準

## 1. 概要

- 要件名: select-best-photo
- 正本: `docs/requirements.md`
- 技術スタック参照: `docs/tech-stack.md`

信頼性レベルは `docs/spec/select-best-photo/requirements.md` と同じ定義を使う。

## 2. ペア利用開始

- Given ユーザーが初回起動する場合、When アプリ利用を開始する、Then Firebase Anonymous Authenticationで内部ユーザーとして識別される。🔵
- Given ユーザーがペアを作成する場合、When ペア作成を実行する、Then 相手が入力できるペアコードが発行される。🔵
- Given 相手からペアコードを受け取っている場合、When ユーザーがペアコードを入力する、Then 同じカップルデータに参加できる。🔵
- Given ペア参加済みの場合、When 片方の入力状態が変わる、Then もう片方の端末でも入力状態が同期される。🔵

## 3. 月間ベスト

- Given 月間ベスト件数が5件に設定されている場合、When 自分が月間ベストを登録する、Then 最大5件まで登録できる。🔵
- Given 月間ベスト件数が5件に設定されている場合、When 相手が月間ベストを登録する、Then 相手も最大5件まで登録できる。🔵
- Given 月間ベストを入力する場合、When 入力画面を開く、Then 下位順位から順番に写真・動画を選択できる。🔵
- Given 月間ベストを入力中の場合、When 選択済み内容を確認する、Then 選択済みの写真・動画と順位を見返せる。🔵
- Given 月間ベストを入力中または入力完了後の場合、When 自分の入力を修正する、Then 選んだ写真・動画や順位を変更できる。🔵
- Given 相手の月間ベストが存在する場合、When 自分が相手の入力を編集しようとする、Then 編集できない。🔵
- Given 月間データをリセットしようとする場合、When ユーザーがリセット操作を実行する、Then 対象月の全体リセットであることを示す確認ダイアログが表示される。🔵
- Given 月間データをリセットした場合、When 両方のユーザーが再入力を完了する、Then 月間結果発表をもう一度見られる。🔵

## 4. 入力状態と公開条件

- Given ユーザーが未入力の場合、When 入力状態を確認する、Then 未入力として表示される。🔵
- Given ユーザーが入力を開始して完了していない場合、When 入力状態を確認する、Then 入力中として表示される。🔵
- Given ユーザーが入力完了した場合、When 入力状態を確認する、Then 入力完了として表示される。🔵
- Given 片方のユーザーだけが入力完了している場合、When 結果発表画面を開く、Then 相手の結果は表示されない。🔵
- Given 相手が入力途中の場合、When 入力状況を確認する、Then 相手の入力内容は表示されず入力中であることだけが表示される。🔵
- Given 両方のユーザーが入力完了している場合、When 結果発表画面を開く、Then 互いの結果が表示される。🔵
- Given 両方の入力完了前の場合、When Firestoreから結果データを取得しようとする、Then Security Rulesで公開条件に反する読み取りを防ぐ。🔵

## 5. 結果発表

- Given 両方のユーザーが月間ベストを入力完了している場合、When 月間結果発表画面を開く、Then 下位から順番に結果が表示される。🔵
- Given 両方のユーザーが年間ベストを入力完了している場合、When 年間結果発表画面を開く、Then 年間TOP5が順位付きで表示される。🔵
- Given 両方のユーザーがカスタム部門TOP3を入力完了している場合、When カスタム部門結果発表画面を開く、Then 部門別TOP3が順位付きで表示される。🔵
- Given 過去結果が存在する場合、When ユーザーが再視聴を選ぶ、Then リセットなしで結果発表演出を再視聴できる。🔵

## 6. 年間ベスト候補と年間TOP5

- Given 年間候補設定で2025年7月が2件、2025年8月が1件の場合、When 年間ベスト候補を選ぶ、Then 各月の設定件数に従って候補を選べる。🔵
- Given 月間ベスト件数が10件、年間候補件数が2件の場合、When 年間ベスト候補を選ぶ、Then 月間ベスト件数とは別に最大2件まで候補へ進められる。🔵
- Given 年間ベスト候補が存在する場合、When 年間ベストを選ぶ、Then 自分と相手はそれぞれ年間TOP5を選べる。🔵
- Given 年間ベストを入力する場合、When 入力画面を開く、Then 下位順位から順番に写真・動画を選択できる。🔵
- Given 年間ベスト入力中の場合、When 選択済み内容を確認する、Then 選択済みの写真・動画と順位を見返せる。🔵
- Given 年間ベストをリセットしようとする場合、When ユーザーがリセット操作を実行する、Then 対象年の年間ベスト全体リセットであることを示す確認ダイアログが表示される。🔵
- Given 年間ベストをリセットした場合、When 両方のユーザーが再入力を完了する、Then 年間ベスト結果発表をもう一度見られる。🔵

## 7. メディア型カスタム部門

- Given カスタム部門が存在する場合、When 部門別TOP3を選ぶ、Then 年間ベスト候補に入った写真・動画からTOP3を選べる。🔵
- Given カスタム部門TOP3を入力する場合、When 入力画面を開く、Then 下位順位から順番に写真・動画を選択できる。🔵
- Given カスタム部門入力中の場合、When 選択済み内容を確認する、Then 選択済みの写真・動画と順位を見返せる。🔵
- Given カスタム部門TOP3をリセットしようとする場合、When ユーザーがリセット操作を実行する、Then 対象部門の全体リセットであることを示す確認ダイアログが表示される。🔵
- Given カスタム部門TOP3をリセットした場合、When 両方のユーザーが再入力を完了する、Then カスタム部門結果発表をもう一度見られる。🔵

## 8. テキスト候補型カスタム部門

- Given テキスト候補型カスタム部門が存在する場合、When 候補項目を追加する、Then `.xlsx`、`.csv`、手入力のいずれかで候補項目を追加できる。🔵
- Given 候補項目ファイルを読み込む場合、When 読み込みを実行する、Then 候補名を候補項目として追加できる。🔵
- Given アプリ上で候補項目を入力または編集する場合、When 関連画像を添付する、Then 任意で画像を候補項目に紐づけられる。🔵
- Given 候補項目に関連画像を添付する場合、When 画像を選択する、Then 1候補につき1枚の画像を紐づけられる。🔵
- Given ExcelまたはCSVから読み込んだ候補項目が存在する場合、When アプリ上で関連画像を添付する、Then その候補項目に画像を紐づけられる。🔵
- Given テキスト候補型カスタム部門が存在する場合、When ポイント設定を行う、Then 順位ごとのポイントを部門ごとに設定できる。🔵
- Given テキスト候補型カスタム部門が存在する場合、When 入力対象順位を設定する、Then 何位まで入力するかを部門ごとに設定できる。🔵
- Given テキスト候補型カスタム部門が存在する場合、When 発表対象順位を設定する、Then 何位までを結果発表に含めるかを部門ごとに設定できる。🔵
- Given 自分と相手がテキスト候補型カスタム部門を入力完了している場合、When 結果発表画面を開く、Then 部門ごとのポイント設定に従って集計結果が表示される。🔵
- Given テキスト候補型カスタム部門をリセットしようとする場合、When ユーザーがリセット操作を実行する、Then 対象部門の全体リセットであることを示す確認ダイアログが表示される。🔵

## 9. 敗者復活枠

- Given 敗者復活枠の件数が2件の場合、When 敗者復活枠を選ぶ、Then 全ての写真・動画から最大2件を選べる。🔵
- Given 敗者復活枠が選択されている場合、When 年間ベストTOP5を選ぶ、Then 敗者復活枠の写真・動画が候補に含まれる。🔵
- Given 敗者復活枠が選択されている場合、When メディア型カスタム部門を選ぶ、Then 敗者復活枠の写真・動画が候補に含まれる。🔵
- Given 敗者復活枠をリセットしようとする場合、When ユーザーがリセット操作を実行する、Then 対象年の敗者復活枠全体リセットであることを示す確認ダイアログが表示される。🔵
- Given リセットにより不要になったStorageメディアがある場合、When リセット処理が完了する、Then 不要な派生メディアだけがFirebase Cloud Storageから削除され、端末またはiCloud写真ライブラリ上の元データは削除されない。🔵

## 10. メディアと保存

- Given ユーザーが写真を選択した場合、When アプリに登録する、Then 表示用に圧縮した画像がStorageへ保存される。🔵
- Given ユーザーが動画を選択した場合、When アプリに登録する、Then アプリ上で再生可能な圧縮版動画がStorageへ保存される。🔵
- Given ユーザーがLive Photosを選択した場合、When アプリに登録する、Then 通常写真として潰さず、アプリ上でLive Photosとして再生可能な形式で静止画部分とモーション部分が対応付けて保存される。🔵
- Given 登録済みメディアが存在する場合、When 写真を開く、Then アプリ上で写真を表示できる。🔵
- Given 登録済みメディアが存在する場合、When 動画を開く、Then アプリ上で動画を再生できる。🔵
- Given 登録済みメディアが存在する場合、When Live Photosを開く、Then アプリ上でLive Photosを再生できる。🔵
- Given メディアを登録する場合、When アップロード前確認を表示する、Then ユーザーはFirebaseへ送信される対象を認識できる。🔵
- Given 元データが写真ライブラリまたはiCloud写真に存在する場合、When アプリで登録、編集、リセット、Storage削除を行う、Then 写真ライブラリおよびiCloud写真上の元データは変更または削除されない。🔵
- Given 実装が写真ライブラリへアクセスする場合、When メディアを選択または読み込む、Then 写真ライブラリの削除・変更系APIを使用しない。🔵

## 11. 非機能、検証、運用

- Given iPhoneでアプリを利用する場合、When 主要画面を表示する、Then iPhone向けレイアウトとして破綻しない。🔵
- Given Dynamic Typeが有効な場合、When 主要画面を表示する、Then 主要な操作と情報が利用できる。🔵
- Given VoiceOverが有効な場合、When 主要操作を行う、Then 操作対象と状態が理解できる。🔵
- Given Firebase Security Rulesが設定されている場合、When ペア外ユーザーがデータへアクセスする、Then 読み書きが拒否される。🔵
- Given ログ出力が行われる場合、When ペアコード、ユーザーID、写真パス、個人情報を扱う、Then それらを不用意にログへ出力しない。🔵
